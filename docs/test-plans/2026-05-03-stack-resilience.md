# Stack-resilience human test plan

Generated by `test-analyst` after the stack-resilience plan landed (8 phases + audit fixes).

Coverage validation: **PASS** — 49/49 automated criteria covered by inline phase-task verifications + the `dotfiles stacks doctor` recipe; 4 mixed criteria (AC1.3, AC1.4, AC2.10, AC2.11) have human-verification halves walked through below.

## Prerequisites

- Mac mini (or equivalent host) with this dotfiles repo at `~/Developer/dotfiles`.
- Colima VMs `shared` and `bridged` already running (`dotfiles stacks vm-up`).
- All four stacks already up (`dotfiles stacks up-all`) and healthy (`dotfiles stacks doctor` exits 0).
- `stacks/adguard/.env` populated with a valid `TAILSCALE_PAT`.
- LAN access to the RT-AC68U admin UI (typically `http://router.local` or the router's LAN IP).
- An iOS device signed into the same Apple ID as the Home you want to verify pairing for.
- Pre-migration knowledge: at least one freshrss feed and one wallabag saved-article that existed before the bind-mount migration, so you can confirm data preservation.

## End-to-End: New-device fresh setup (AC7.4, AC7.5)

Validates that the staged setup walkthrough works for someone with no codebase context.

1. On a borrowed Mac (or a fresh user account), `brew install just stow neovim zellij zsh-completions`.
2. `git clone <repo> ~/Developer/dotfiles && cd ~/Developer/dotfiles`.
3. `just -f $(pwd)/justfile stow setup-base` — confirm only the `base` package is stowed.
4. `source ~/.zshrc` — `dotfiles` alias is now defined.
5. `dotfiles stow setup-colima` — only `colima` package stowed.
6. `brew install colima docker socket_vmnet gettext jq tailscale-cli && sudo brew services start socket_vmnet`.
7. `dotfiles stacks vm-up` — both Colima VMs start.
8. For each stack you want, `cp .env.example .env && chmod 600 .env`, edit, then follow that stack's README.
9. `dotfiles stacks backup-install`.
10. `dotfiles stacks doctor` — should exit 0 (stacks not brought up will WARN on .env, not FAIL).

## End-to-End: Backup → corrupt → restore round-trip (AC1.5, AC1.11, AC1.12)

Validates the full backup/restore loop on a stack you can afford to take down.

1. Pick a low-stakes stack (e.g., wallabag). Run `dotfiles stacks wallabag backup` twice; each exits 0, today-dated tarball mtime updated, no duplicate (AC1.12).
2. `dotfiles stacks wallabag down`.
3. `mv ~/.volumes/wallabag ~/.volumes/wallabag.disaster` (simulate data loss).
4. `dotfiles stacks wallabag restore ~/.volume-backups/daily/wallabag-<today>.tgz` — exit 0 (destination empty).
5. `dotfiles stacks wallabag up && dotfiles stacks wallabag bootstrap` (if needed).
6. Browser-confirm wallabag works. Then `rm -rf ~/.volumes/wallabag.disaster`.
7. Re-run `dotfiles stacks wallabag restore ~/.volume-backups/daily/wallabag-<today>.tgz` against the now-populated `~/.volumes/wallabag/` — exit 1, "is not empty; pass --force" (AC1.11).
